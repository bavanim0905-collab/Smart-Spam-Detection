Chapter 1: Introduction

1.1 Project Overview

In the contemporary digital landscape, mobile communication has become an indispensable facet of human life. Short Message Service (SMS), despite the rise of instant messaging platforms, remains the primary channel for critical transactions, government alerts, and two-factor authentication. However, this ubiquity has birthed a massive surge in fraudulent activities. Every year, billions of dollars are lost globally due to SMS-based phishing (Smishing) and unsolicited promotional spam.

SpamScanner is an innovative Android application engineered to solve this crisis using Edge Artificial Intelligence. By deploying a deep learning model directly onto the mobile handset, it achieves the rare trifecta of absolute user privacy, zero-latency processing, and high-accuracy classification without requiring a single byte of data to leave the device.

1.2 Problem Statement

Traditional SMS filtering methods typically fall into two flawed categories:

  1. Keyword Blacklists: Highly brittle. Spammers easily bypass these by using subtle variations (e.g., "W1NNER" instead of "WINNER").
  2. Cloud-Based Filters: Privacy-invasive. They require reading the user's private messages and uploading them to remote servers, exposing financial secrets and personal identities to potential data breaches.

1.3 Objectives

  • To design an end-to-end SMS management system with real-time classification.
  • To implement a TensorFlow Lite model that distinguishes between HAM, SPAM, and SMISHING.
  • To ensure 100% data privacy by performing all computations locally.
  • To provide an intuitive, Material 3-based user interface for seamless message handling.

1.4 Motivation

The motivation for this project stems from the increasing sophistication of social engineering attacks. Modern "Smishing" messages often mimic banking alerts so perfectly that even tech-savvy users fall victim. A local AI model can analyze the underlying intent and linguistic patterns of a message, providing a proactive shield that keyword filters cannot match. Furthermore, the development of TensorFlow Lite has made it possible to run complex neural networks on mid-range smartphones, democratizing advanced security tools.

1.5 Scope of the Project

The scope encompasses the following:

  • Dataset Preprocessing: Cleaning and tokenizing thousands of SMS samples for model training.
  • Model Optimization: Quantizing the neural network to fit within mobile memory constraints.
  • Android Telephony Integration: Utilizing the BroadcastReceiver and ContentObserver APIs to synchronize with the system's SMS provider.
  • Persistence: Designing a robust Room database for message indexing.

Chapter 3: System Specification

3.1 Hardware Environment

The system is designed to run on a variety of Android devices. However, for real-time AI inference, certain thresholds are required:

  • CPU: Octa-core ARM Cortex processor (preferably with an NPU).
  • RAM: Minimum 4GB for maintaining the TFLite model in memory without eviction.
  • Storage: 64GB+ (SSD/UFS) to ensure fast database query execution.

3.2 Software Environment

3.2.1 Development Stack

  • Language: Kotlin (v1.9.22)
  • UI Framework: Jetpack Compose 1.6.0
  • Machine Learning: TensorFlow Lite 2.15.0
  • Architecture: MVVM (Model-View-ViewModel)
  • Local DB: Room Persistence Library
  • Background Jobs: WorkManager

3.2.2 Backend Environment (Logic & Data)

The "Backend" of this application is self-contained within the Android ecosystem. It leverages the SQLite-based Room database for structured storage and the TFLite runtime for algorithmic execution. This local backend ensures that no external API calls are necessary for the app's core functionality.

5.3 Machine Learning Model Design

The model is a Deep Neural Network trained on the UCI SMS Spam Collection and augmented with local Smishing datasets. It uses a **Embedding layer** followed by **Dense layers** with ReLU activation. The output is a Softmax layer providing probabilities for the three classes.

Chapter 6: System Implementation

6.1 AI Implementation (SmsClassifier)

The SmsClassifier object is a singleton that manages the lifecycle of the TFLite Interpreter. It handles the critical task of **Tokenization**—converting text into a fixed-size vector that the neural network can process.

// SMS Tokenization Logic
private fun tokenize(text: String): IntArray {
    val words = text.lowercase().split(Regex("\W+"))
    val tokens = words.map { vocab?.get(it) ?: 1 } // 1 = 
    val arr = IntArray(200) { 0 } // Fixed input size 200
    for (i in tokens.indices) {
        if (i < 200) arr[i] = tokens[i]
    }
    return arr
}

6.2 Background Worker Implementation

To ensure notifications are sent even when the app is closed, we use WorkManager. This component is triggered by the SmsReceiver and performs the inference in a separate process.

class SpamWorker(context, params) : Worker(context, params) {
    override fun doWork(): Result {
        val text = inputData.getString("sms_text") ?: return Result.failure()
        val (label, confidence) = SmsClassifier.predict(text)
        if (label == "SPAM" && confidence > 0.8) {
            sendNotification("Spam Alert", text)
        }
        return Result.success()
    }
}
